## 介绍

Fumadocs <span className='text-fd-muted-foreground text-sm'>(Foo-ma docs)</span> 是一个**文档框架**，旨在快速、灵活，并能无缝集成到您的 React 框架中。

Fumadocs 包含不同的部分：

<Cards>

<Card icon={<CpuIcon className="text-purple-300" />} title='Fumadocs Core'>

Handles most of the logic, including document search, content source adapters, and Markdown extensions.

</Card>

<Card icon={<PanelsTopLeft className="text-blue-300" />} title='Fumadocs UI'>

The default theme of Fumadocs offers a beautiful look for documentation sites and interactive components.

</Card>

<Card icon={<Database />} title='Content Source'>

The source of your content, can be a CMS or local data layers like [Fumadocs MDX](/docs/mdx) (the official content source).

</Card>

<Card icon={<Terminal />} title='Fumadocs CLI'>

A command line tool to install UI components and automate things, useful for customizing layouts.

</Card>

</Cards>

<Callout title="Want to learn more?">
  Read our in-depth [What is Fumadocs](/docs/ui/what-is-fumadocs) introduction.
</Callout>

### 术语

**Markdown/MDX：** Markdown 是一种用于创建格式化文本的标记语言。Fumadocs 原生支持 Markdown 和 MDX（Markdown 的超集）。

**[Bun](https://bun.sh)：** 一个 JavaScript 运行时，我们用它来运行脚本。

虽然不是必需的，但一些 React.js 的基础知识将有助于进一步的定制。

## 自动安装

需要 Node.js 20 的最低版本，请注意 Node.js 23.1 可能与 Next.js 存在兼容性问题。

```bash tab="npm"
npm create fumadocs-app
```

```bash tab="pnpm"
pnpm create fumadocs-app
```

```bash tab="yarn"
yarn create fumadocs-app
```

```bash tab="bun"
bun create fumadocs-app
```

安装程序会询问您：

- 要使用的 React.js 框架（推荐 Next.js）
- 要使用的内容源

一个新的 fumadocs 应用将被初始化。现在您可以开始开发了！

<Callout title='From Existing Codebase?'>

    You can follow the [Manual Installation](/docs/ui/manual-installation) guide to get started.

</Callout>

### 开始使用！

在 docs 文件夹中创建您的第一个 MDX 文件。

```mdx title="content/docs/index.mdx"
---
title: Hello World
---

## Yo what's up
```

在开发模式下运行应用并访问 http://localhost:3000/docs。

```npm
npm run dev
```

## 常见问题

您可能会遇到的一些常见问题。

<Accordions>

  <Accordion id='change-base-url' title="如何更改文档的基础路由？">

    路由由您的 React 框架处理，您需要先更改路由结构。

    例如，在 Next.js 中，重命名路由（`/docs/*` -> `/info/*`）：

    <Files>
      <Folder name="app/docs" defaultOpen className="opacity-50" disabled>
        <File name="layout.tsx" />
      </Folder>
      <Folder name="app/info" defaultOpen>
        <File name="layout.tsx" />
      </Folder>
    </Files>

    或者使用路由组将 `/docs/*` 重命名为 `/*`：

    <Files>
      <Folder name="app/(docs)" defaultOpen>
        <File name="layout.tsx" />
      </Folder>
    </Files>

    最后，更新 `source.ts` 中页面的基础 URL：

```ts title="lib/source.ts"
import { loader } from 'fumadocs-core/source';

export const source = loader({
  baseUrl: '/info', // 更新为新值 [!code highlight]
});
```

  </Accordion>

    <Accordion id='multi-docs' title="如何实现多文档？">
        我们推荐使用 [侧边栏选项卡](/docs/ui/navigation/sidebar#sidebar-tabs)。
    </Accordion>

</Accordions>

### 对于 Next.js

<Accordions>
  <Accordion id='dynamic-route' title="它使用了动态路由，性能会差吗？">

    当配置了 `generateStaticParams` 时，Next.js 会将动态路由转换为静态路由。
    因此，它的速度与静态页面一样快。

    你可以在 Next.js 上[启用静态导出](/docs/ui/static-export)以获得静态构建输出。

  </Accordion>
  <Accordion id='custom-layout-docs-page' title='如何在 /docs 中创建一个不使用文档布局的页面？'>

    与在 Next.js App Router 中管理布局相同，从内容目录（`/content/docs`）中移除原始的 MDX 文件。
    这确保了重复的页面不会导致错误。

    现在，你可以将页面添加到另一个路由组，该路由组不是文档布局的后代。

    例如，要替换 `/docs/test`：

    <Files>
      <File name="(home)/docs/test/page.tsx" />
      <Folder name="docs">
        <File name="layout.tsx" />
        <File name="[[...slug]]/page.tsx" />
      </Folder>
    </Files>

    对于 `/docs`，你需要将全捕获路由更改为非可选的：

    <Files>
      <File name="(home)/docs/page.tsx" />
      <Folder name="docs" defaultOpen>
        <File name="layout.tsx" />
        <File name="[...slug]/page.tsx" />
      </Folder>
    </Files>

  </Accordion>

</Accordions>

### 升级 Fumadocs

当你遇到任何问题或尝试新功能时，请确保升级 Fumadocs：

```bash title="pnpm"
pnpm update -i -r --latest
```
