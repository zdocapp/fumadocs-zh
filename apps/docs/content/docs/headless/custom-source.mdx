## 介绍

**Fumadocs 非常灵活。** 您可以与任何内容源集成，即使没有官方适配器。

### 示例

您可以查看使用 Fumadocs 与 CMS 的示例，这能提供良好的内容发布体验，并且无需重新构建应用即可实现实时更新。

- [BaseHub](https://github.com/fuma-nama/fumadocs-basehub)
- [Sanity](https://github.com/fuma-nama/fumadocs-sanity)
- [Payload CMS](https://github.com/MFarabi619/fumadocs-payloadcms)

对于自定义内容源的实现，您需要：

### 页面树

您可以硬编码页面树，或者编写一些代码来生成一个。
请参阅[页面树的定义](/docs/headless/page-tree)。

将您的页面树传递给 `DocsLayout`（通常在 `layout.tsx` 中）：

```tsx title="layout.tsx"
import { DocsLayout } from 'fumadocs-ui/layouts/docs';
import type { ReactNode } from 'react';

export default function Layout({ children }: { children: ReactNode }) {
  return (
    <DocsLayout
      // [!code ++:5]
      tree={
        {
          // your own tree
        }
      }
    >
      {children}
    </DocsLayout>
  );
}
```

页面树类似于更智能的“侧边栏项”，它们将在 UI 中的导航元素（如页面页脚）中被引用。

### 文档页面

对于文档页面，逻辑相同：

- 定义路径参数（`slugs`）。
- 根据路径参数获取页面内容。
- 渲染内容。
- （可选）为您的框架配置预渲染。

#### 主体

在页面的主体部分，根据 slug 找到相应的页面，并在 `DocsPage` 组件内渲染其内容。

您还需要目录功能，可以通过自行实现或使用 [`getTableOfContents`](/docs/headless/utils/get-toc) 工具（仅限 Markdown/MDX）来生成。

```tsx
import { DocsPage, DocsBody } from 'fumadocs-ui/page';
import { getPage } from './my-content-source';
import { notFound } from 'next/navigation';

export default function Page({ params }: { params: { slug?: string[] } }) {
  const page = getPage(params.slug);
  if (!page) notFound();

  return (
    <DocsPage toc={page.tableOfContents}>
      <DocsBody>{page.render()}</DocsBody>
    </DocsPage>
  );
}
```

#### 预渲染（仅限 Next.js）

定义 [`generateStaticParams`](https://nextjs.org/docs/app/api-reference/functions/generate-static-params) 函数。
它应返回一个参数列表（`params`）来填充 `[[...slug]]` 全捕获路由。

### 文档搜索

考虑到您的内容可能不一定是 Markdown/MDX，这可能会比较困难。
对于 Markdown 和 MDX，内置的[搜索 API](/docs/headless/search/orama) 足以满足大多数用例。
否则，您需要自行实现。

我们推荐使用第三方解决方案，如 Orama 或 Algolia Search。它们比内置的搜索 API 更灵活，并且更容易与远程源集成。
Fumadocs 提供了一个简单的 [Algolia 搜索适配器](/docs/headless/search/algolia)，其中包含一个搜索客户端，可与 Fumadocs UI 集成。

## MDX Remote

Fumadocs 提供 **MDX Remote** 包，它是一个帮助程序，用于将基于 Markdown 的内容源与 Fumadocs 集成。
您可以将其视为带有 Fumadocs 内置插件的 `next-mdx-remote`。

### 设置

```package-install
@fumadocs/mdx-remote
```

它提供的主要功能是 MDX 编译器，可以将 MDX 内容编译为 JSX 节点。
由于它不使用打包器，因此存在一些限制：

- MDX 文件中无需导入和导出。

它与服务器组件兼容。例如：

```tsx
import { compileMDX } from '@fumadocs/mdx-remote';
import { getPage } from './my-content-source';
import { DocsBody, DocsPage } from 'fumadocs-ui/page';
import { getMDXComponents } from '@/mdx-components';

export default async function Page({
  params,
}: {
  params: { slug?: string[] };
}) {
  const page = getPage(params.slug);
  const compiled = await compileMDX({
    source: page.content,
  });

  const MdxContent = compiled.body;

  return (
    <DocsPage toc={compiled.toc}>
      <DocsBody>
        <MdxContent components={getMDXComponents()} />
      </DocsBody>
    </DocsPage>
  );
}
```

#### 图片

在 Vercel 等无服务器平台上，原始的 `public` 文件夹（包括图片等静态资源）在生产构建后会被移除。
`compileMDX` 可能无法再访问 `public` 中的本地图片。

引用图片时，请确保使用 URL。
