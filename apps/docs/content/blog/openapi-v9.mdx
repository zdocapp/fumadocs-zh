## 概述

此次重大变更主要旨在解决 `generateFiles()` 函数的问题。

此前，它是一个简单的函数，用于从您的 OpenAPI 模式生成多个 MDX 文件/页面，与每个文档生成器相同。
我们在公共 OpenAPI 模式（如 Unkey、Vercel 以及 Scalar 和 Swagger 的 Museum 模式示例）上对其进行了测试。

由于这些模式是为不同的文档解决方案编写的，甚至是他们自定义的解决方案。
我们使得 `generateFiles()` 过于复杂，难以对各种模式风格产生最佳结果，并且更难自定义生成的 API 文档文件路径。

此更新还包括：

- 更好的模式与 Playground 主体输入的用户界面
- 改进的 `generateFiles()` 类型安全性

## 重大变更

生成文件路径的算法已更改：

- 将不再生成 `meta.json`，请根据需要自行添加。
- `per: operation`：生成的路径将与您的操作 ID 相同。如果未定义，则使用您的端点路径。

### 分组方式

`groupBy` API 的行为也已更改。

| 值    | 输出                                              |
| ----- | ------------------------------------------------- |
| tag   | `{tag}/{operationId ?? endpoint_path}.mdx`        |
| route | `{endpoint_path}/{method}.mdx` (忽略 `name` 选项) |
| none  | `{operationId ?? endpoint_path}.mdx` (默认)       |

### 自定义输出

`name` 选项的用法已更新，可用于自定义文件的输出路径。

```ts
import { generateFiles } from 'fumadocs-openapi';

void generateFiles({
  name: (output, document) => {
    // page info
    console.log(output);
    // parsed OpenAPI schema
    console.log(document);
    return 'my-dir/filename';
  },
});
```

## 迁移

您可以开始使用最新的算法，或者通过以下方式保持当前行为：

```ts
import { generateFiles } from 'fumadocs-openapi';

void generateFiles({
  name: {
    algorithm: 'v1',
  },
});
```

请注意，即使将 `algorithm` 设置为 `v1`，也不会再创建 `meta.json`，您可以保留当前生成的 `meta.json` 文件。
