## 为什么？

受到 [Shadcn UI](https://ui.shadcn.com) 的启发，我决定让 Fumadocs 更易于使用，提供更多简化设计的 API。

这是一个重大更新。

## 新特性

### Fumadocs CLI

将 Fumadocs UI 组件克隆到您的工作区并进行修改。

```package-install
npm install @fumadocs/cli --save-dev
```

```bash
pnpm fumadocs add
```

详情请参阅[文档](/docs/cli)。

### 侧边栏选项卡

之前，多页面树是通过 Fumadocs UI 的 `RootToggle` 组件实现的。
您必须将其添加到侧边栏横幅中，这不如其他 API 直观。

通过侧边栏选项卡，只需创建一个根文件夹，Fumadocs 就会立即在侧边栏中添加一个选项卡组件。

```json title="meta.json"
{
  "root": true,
  "title": "Tab Name",
  "description": "Some text about the tab",
  "icon": "IconName"
}
```

### Orama

我们将内置搜索从 Flexsearch 迁移到了 Orama，这是为 Node.js 文档网站提供支持的相同搜索引擎。
它是开源的，并且还提供云集成。

无需任何更改。
您可以使用我们新的 `createFromSource` API 来创建路由处理程序，该 API 无需任何配置即可提供国际化支持。

```ts
import { source } from '@/lib/source';
import { createFromSource } from 'fumadocs-core/search/server';

export const { GET } = createFromSource(source);
```

为此，Fumadocs 引入了新的搜索客户端，支持不同的 API 客户端。
这包括 Algolia、Orama（静态和通过路由处理程序的动态搜索）。

```ts
import { useDocsSearch } from 'fumadocs-core/search/client';

const client = useDocsSearch({
  type: 'static',
});
```

请参阅[搜索 API](/docs/headless/search)。

### 静态搜索

对于静态导出的站点，您无法使用路由处理器。
我们现在支持使用构建时生成的搜索索引进行客户端搜索。

参见[静态搜索](/docs/headless/search/orama#static-export)。

### 更少的依赖

我一直在努力减少 Fumadocs 所需的依赖项，这也是我们将 Fumadocs 拆分为不同包的原因之一。

Fumadocs UI 现在捆绑了来自 `lucide-react` 的图标，对于不使用 Lucide 的 Next.js 应用，它们可以避免下载整个图标库。

并且搜索客户端不再使用 `swr`，我们实现了一个轻量级的 `useQuery` hook，特别注重 React 性能优化。

### 新的元数据图像 API

为了改进代码组织，我们在 Fumadocs Core 上创建了一个元数据图像 API。
它是 Next.js 元数据 API 的一个微小封装，与源 API 无缝组合。

```ts title="lib/metadata.ts"
import { createMetadataImage } from 'fumadocs-core/server';
import { source } from '@/lib/source';

export const metadataImage = createMetadataImage({
  imageRoute: '/docs-og',
  source,
});
```

```ts title="route.ts"
import { generateOGImage } from 'fumadocs-ui/og';
import { metadataImage } from '@/lib/metadata';

export const GET = metadataImage.createAPI((page) => {
  return generateOGImage({
    title: page.data.title,
    description: page.data.description,
    site: 'My App',
  });
});

export function generateStaticParams() {
  return metadataImage.generateParams();
}
```

```tsx title="page.tsx"
import { source } from '@/lib/source';
import { metadataImage } from '@/lib/metadata';
import { notFound } from 'next/navigation';

export function generateMetadata({ params }: { params: { slug?: string[] } }) {
  const page = source.getPage(params.slug);
  if (!page) notFound();

  return metadataImage.withImage(page.slugs, {
    title: page.data.title,
    description: page.data.description,
  });
}
```

为此，`fumadocs-ui/og` 中的 `getImageMeta` 函数已被移除。

### 简写形式

您可能已经注意到，我们引入了更多抽象来减少启用某些功能所需的设置步骤。
这也是 Fumadocs CLI 代码生成器正常工作所必需的。

就像 `generateParams` 函数，它为 Next.js 的 `generateStaticParams` 提供了零配置的国际化支持。

```ts
import { source } from '@/lib/source';

export function generateStaticParams() {
  return source.generateParams();
}
```

### 更好的卡片组件

Fumadocs UI 卡片现在支持不带 `href` 的使用方式。
您可以将子元素作为 React 节点传递，排版样式将正确应用。

```mdx
<Card icon={<Database />} title='Content Source'>

The input/source of your content, it can be a CMS, or local data layers like [Content Collections](https://www.content-collections.dev) and [Fumadocs MDX](/docs/mdx).

</Card>
```

### 更优的分类组件

原有的 `DocsCategory` 组件是从我们的官方文档中复制的，这是一个非常简单的实现，没有考虑页面树结构。

现在它通过 `from` 属性接受源对象。

```tsx title="page.tsx"
import { source } from '@/lib/source';
import { DocsCategory } from 'fumadocs-ui/page';

const page = source.getPage(params.slug);

<DocsCategory page={page} from={source} />;
```

默认情况下，它会从 `page` 中获取 `locale` 属性来查找对应的页面树进行遍历。
您也可以强制指定一个页面树。

```tsx title="page.tsx (i18n enabled)"
import { source } from '@/lib/source';
import { DocsCategory } from 'fumadocs-ui/page';

const page = source.getPage(params.slug, params.lang);

<DocsCategory page={page} from={source} tree={source.pageTree['en']} />;
```

### OpenAPI 标签显示名称

使用 `x-displayName` 更改显示名称。

```yaml title="openapi.yaml"
tags:
  - name: test
    description: this is a tag.
    x-displayName: My Test Name
```

### 更优的 TypeScript 文档自动化

`AutoTypeTable` 组件现在支持 `type` 属性，您可以在字段内使用 TypeScript：

```mdx
<AutoTypeTable
  path="file.ts"
  name="B"
  type={`
import { ReactNode } from "react"
export type B = ReactNode | { world: string }
`}
/>
```

并且通过 Shiki 支持了 typedoc 中的代码高亮。

我们**强烈建议**使用 `createTypeTable` 而不是在 MDX 文件中导入组件，这样可以共享单个 TypeScript 编译器 API 实例。
请参阅 [自动类型表格](/docs/ui/components/auto-type-table)。

### Next.js 15

Fumadocs v14 与 Next.js 15 兼容，支持动态 API 的同步和异步使用。

<Callout type="info" title="Backward compatible">
  Next.js 14 is also supported, notice that guides/tutorials in the docs are
  mainly for Next.js 15.
</Callout>

## UI 改进

### 导航栏链接

首页布局中的导航菜单经过重新设计，具有更好的动画效果和灵活性。

请参阅[新 API](/docs/ui/navigation)。

![新导航栏](/blog/v14-navbar.png)

### 链接样式

您可以通过 `data-card` 属性为 `a` 标签转义 Tailwind CSS Typography 样式。

```jsx
<a data-card="">
  No styles applied <code>But it does</code>
</a>
```

### 禁用主题切换

您可以在布局中使用 `disableThemeSwitch` 来禁用默认的主题切换器。

## 重大变更

### 从 `defineDocs` 中移除 `dir` 选项

```ts
import { defineDocs } from 'fumadocs-mdx/config';

export const { docs, meta } = defineDocs({
  dir: 'my/content/dir', // define once
});
```

### 重构导入

**先前版本**

```ts
import { DocsLayout } from 'fumadocs-ui/layout';
import { HomeLayout } from 'fumadocs-ui/home-layout';
import { HomeLayoutProps } from 'fumadocs-ui/home-layout';
```

**新的导入路径**

```ts
import { DocsLayout } from 'fumadocs-ui/layouts/docs';
import { HomeLayout } from 'fumadocs-ui/layouts/home';
import { BaseLayoutProps } from 'fumadocs-ui/layouts/shared';
```

### Twoslash UI

我们将 Twoslash UI 组件迁移到了 `fumadocs-twoslash`。
这从 Fumadocs UI 中分离了一些逻辑，实现了更好的代码组织。

请以不同方式导入 CSS 样式和 `Popup` 组件。

```ts
import 'fumadocs-twoslash/twoslash.css';

import { Popup } from 'fumadocs-twoslash/ui';
```

<Callout>此功能需要 Tailwind CSS。</Callout>

### 移除已弃用的 API

之前的 `createI18nSearchAPIExperimental` 现已重命名为 `createI18nSearchAPI`。
它现在接收 i18n 配置，而不是将选项分散在各处。

`fumadocs-core/search/shared` 中的类型已移至 `fumadocs-core/server`。
