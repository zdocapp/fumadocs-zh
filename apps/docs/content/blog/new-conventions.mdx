## `mdx-component.tsx`

有时会有初学者提出疑问，对在哪里添加 MDX 组件感到困惑。
虽然它简单地位于 `page.tsx` 中，这应该不难找到，但我认为某种约定可能会有所帮助，因此我决定重新添加 `mdx-components.tsx`。

我喜欢更少的文件，但考虑到 `create-fumadocs-app` 也应该作为初学者的起点，他们可能不熟悉 MDX，默认提供它会更有帮助。

### 现有项目

该约定是可选的（仅为了使学习曲线更平滑）。
对于现有用户，您可能已经知道如何传递 MDX 组件，无需进一步更改。

但您仍然可以创建一个：

```tsx title="mdx-components.tsx"
import defaultMdxComponents from 'fumadocs-ui/mdx';
import type { MDXComponents } from 'mdx/types';

export function getMDXComponents(components?: MDXComponents): MDXComponents {
  return {
    ...defaultMdxComponents,
    ...components,
  };
}
```

并在您的 MDX 组件中使用它。

```tsx title="page.tsx"
import { getMDXComponents } from '@/mdx-components';

<MDXContent
  components={getMDXComponents({
    // extend it
  })}
/>;
```

## 弃用 `<I18nProvider />`

我们现在更倾向于使用单一的 `<RootProvider />` 来处理所有事情，通过 `i18n` 属性取代了 `<I18nProvider />` 的需求。

```tsx
<RootProvider
  i18n={
    // i18n provider props
  }
>
  {children}
</RootProvider>
```

这使得根提供者能够正确处理层次结构，而不会暴露太多复杂性，例如，正确的顺序应该是：

```tsx
<FrameworkProvider>
  <ThemesProvider>
    <I18nProvider>
      <SidebarProvider>
        <SearchProvider>{children}</SearchProvider>
      </SidebarProvider>
    </I18nProvider>
  </ThemesProvider>
</FrameworkProvider>
```

更改不同提供者的层次结构可能会导致问题，因为它们实际上相互依赖，现在所有内容都集成到 `<RootProvider />` 中，包括 I18n 配置。

新的[国际化](/docs/ui/internationalization)指南要求 Fumadocs 15.2.3 或更高版本。
