## 概述

v15 版本的主要目的是支持 Tailwind CSS v4。
Tailwind CSS v4 对其 API 和内部结构进行了全面重新设计，以完全遵循新的 CSS 优先配置风格，因此需要进行破坏性变更。

Fumadocs v15 除了将配置迁移至 Tailwind CSS v4 外，没有其他重大变更。

## 重大变更

在进行切换之前，请按照 Tailwind CSS 的[升级指南](https://tailwindcss.com/docs/upgrade-guide)将您的站点升级至 v4 版本。
您可以移除不再使用的 `tailwind.config.js` 文件，并完全依赖新的 CSS 优先配置。

将 Fumadocs UI 导出的预设添加到 `@import` 中，并在源码中包含 `fumadocs-ui` 包。

```css title="Tailwind CSS"
@import 'tailwindcss';
@import 'fumadocs-ui/css/neutral.css';
@import 'fumadocs-ui/css/preset.css';

/* relative to the CSS file, make sure it's correct for your app */
@source '../node_modules/fumadocs-ui/dist/**/*.js';
```

从 v15 开始，您将不再通过 JavaScript 传递选项来自定义插件。
取而代之的是，您可以使用 Tailwind CSS v4 中的新替代方案。

### `addGlobalColors: true`

再次转发颜色：

```css
@theme {
  --color-primary: var(--color-fd-primary);
  /* same for other colors */
}
```

### CSS 变量

Fumadocs 不再使用类似 `--fd-primary: 0 0% 0%` 的 `--fd-<color>` 格式来定义颜色，而是直接在 `@theme` 中定义和使用颜色。
它使用 `hsl()` 替代了之前的格式：

```css
@theme {
  --color-fd-primary: hsl(0, 0%, 100%);
}
```

### 步骤

之前的 Tailwind CSS 工具类如 `steps` 和 `step` 已重命名为 `fd-steps` 和 `fd-step`，以避免冲突。

### 排版

包含 `prose`、`prose-*` 修饰符的排版工具类将继续正常工作。如果它们不再工作或出现意外行为变化，请报告问题。

## 改进

v15 还对 UI 和 OpenAPI 集成进行了一些小改进。

### 代码块标签页

过去，在将代码块分离到标签页时，您需要手动编写 `<Tabs />`。

````mdx
<Tabs items={["Tab 1", "Tab 2"]}>

```ts tab="Tab 1"
console.log('Hello World');
```

```ts tab="Tab 2"
console.log('Hello World');
```

</Tabs>
````

现在您可以这样做：

````mdx
```ts tab="Tab 1"
console.log('Hello World');
```

```ts tab="Tab 2"
console.log('Hello World');
```
````

请注意，对于希望自定义或向 `<Tabs />` 组件传递属性的用户，之前的用法仍然有效。

### `meta.json` 中的反向项

`meta.json` 的 `pages` 属性中的剩余项 `...` 现在支持反向排序：

```json
{
  "pages": ["z...a"]
}
```

### OpenAPI 演练场

v15 改进了演练场 UI（灵感来自 Scalar 的极简主义），并为 Fumadocs OpenAPI 带来了 Scalar API 客户端支持。

您可以在 `createOpenAPI()` 中使用 `useScalar` 选项启用 Scalar API 客户端：

```ts
import { createOpenAPI } from 'fumadocs-openapi/server';
import { APIPlayground } from 'fumadocs-openapi/scalar';

export const openapi = createOpenAPI({
  renderer: {
    APIPlayground,
  },
});
```

并安装和配置他们的 `@scalar/api-client-react`：

```package-install
@scalar/api-client-react
```

```css title="global.css"
@import '@scalar/api-client-react/style.css' layer(base);
```

<Callout>
  Be careful that you must configure Tailwind CSS first, using the pre-built
  stylesheet of Fumadocs UI will conflict with their `style.css` because both
  libraries use Tailwind CSS for styling.
</Callout>

## 未来计划

对于大多数升级到 Tailwind CSS v4 的开发者来说，这次更新应该是一个简单的迁移过程。

未来，我们还希望进一步改进 Fumadocs MDX：

- 移除 `transform` API - 您可以在运行时使用 `.map()` 轻松实现相同功能，例如：

```ts
import { blog } from "@/.source"

export const updatedBlog = blog.map(...)
```

- 移除 Manifest API - 该 API 原本设计用于导出搜索索引，但现在建议使用路由处理程序来实现。

- 更多介绍我们的 [MDX Remote](/docs/headless/custom-source#mdx-remote) 包，它将成为处理大型文档站点性能需求的主要解决方案，这些需求是打包工具无法满足的，包括 MDX 文件的懒编译。
