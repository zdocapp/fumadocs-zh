## 功能特性

- 通过 `source.config.ts`（您内容的新配置文件）实现更多自定义选项。
- 引入**集合（collections）**。
- 支持 Turbopack。
- 支持构建时数据验证。

## 从 v9 迁移

### 重构导入

重构 `next.config` 中的导入。

**从:**

```ts
import createMDX from 'fumadocs-mdx/config';

const withMDX = createMDX();

/** @type {import('next').NextConfig} */
const config = {
  reactStrictMode: true,
};

export default withMDX(config);
```

**到:**

```ts
import { createMDX } from 'fumadocs-mdx/next';

const withMDX = createMDX();

/** @type {import('next').NextConfig} */
const config = {
  reactStrictMode: true,
};

export default withMDX(config);
```

### 移除 `mdx-components.tsx`

`mdx-components.tsx` 不再使用。现在仅允许通过 MDX 主体的 `components` 属性传递 MDX 组件。

```tsx
import defaultMdxComponents from 'fumadocs-ui/mdx';

const MDX = page.data.body;

// set your MDX components with `components` prop
<MDX components={{ ...defaultMdxComponents }} />;
```

这鼓励显式导入 MDX 组件。

以前，`mdx-components.tsx` 通过向每个编译后的 Markdown/MDX 文件注入导入来工作。
这有些多余，因为您始终可以显式导入组件，或者通过 MDX 主体的 `components` 属性替换默认的 HTML 标签（如 `img`）。

### 定义集合

集合现在在源配置文件（`source.config.ts`）中引入。
它指的是文件/内容的集合，例如 Markdown 文件或 JSON/YAML 文件。

每个集合都有自己的配置，您可以使用自定义的 Zod 模式来验证其数据，或者为内容集合设置集合级别的 MDX 选项。

您可以创建一个源配置文件，并添加以下内容：

```ts
import { defineDocs } from 'fumadocs-mdx/config';

export const { docs, meta } = defineDocs({
  dir: 'content/docs',
});
```

`defineDocs` 声明了两个集合：一个使用 `doc` 类型扫描内容文件（例如 `md/mdx`），另一个使用 `meta` 类型扫描元数据文件（例如 `json`）。

现在你可以使用 `fumadocs-mdx` 命令生成类型，建议将其设置为 `postinstall` 脚本。

```json title="package.json"
{
  "scripts": {
    "postinstall": "fumadocs-mdx"
  }
}
```

启动开发服务器时，将生成一个 `.source` 文件夹，其中包含所有已解析的集合/文件。
你可以将其添加到 `.gitignore`，它将取代旧的 `.map` 文件。

要访问这些集合，请从 `source.config.ts` 中按其原始名称导入它们。

```ts
import { docs, meta } from '@/.source';
```

现在要将其与 Fumadocs 框架集成，请将你的 `source.ts` 从：

```ts
import { map } from '@/.map';
import { createMDXSource } from 'fumadocs-mdx';
import { loader } from 'fumadocs-core/source';

export const { getPage, getPages, pageTree } = loader({
  baseUrl: '/docs',
  rootDir: 'docs',
  source: createMDXSource(map),
});
```

改为：

```ts
import { docs, meta } from '@/.source';
import { createMDXSource } from 'fumadocs-mdx';
import { loader } from 'fumadocs-core/source';

export const source = loader({
  baseUrl: '/docs',
  source: createMDXSource(docs, meta),
});
```

- 我们现在建议将 `loader` 的输出直接作为单个变量导出。
- `schema` 选项不再在 `source.ts` 中定义，而是由 `source.config.ts` 处理。
- 它接受两个集合：`docs`（内容）和 `meta`（`meta.json`）。
  如果未使用 `meta`，可以将其留空数组，这样你可以仅定义 `docs` 的集合。

### `page.data`

与 `loader` 一起使用时，你不再需要 `data.frontmatter` 来访问 frontmatter 数据。
它已合并到 `page.data` 对象中。

```ts
page.data.frontmatter.title; // [!code --]
page.data.title; // [!code ++]
```

### MDX 选项

不再将它们传递给 `next.config` 文件，而是在 `source.config.ts` 中定义一个全局配置：

```ts
import { defineConfig } from 'fumadocs-mdx/config';

export default defineConfig({
  mdxOptions: {
    // here!
  },
});
```

### 集合模式

集合的 `schema` 选项允许你自定义验证模式，它接受一个 Zod 类型。

对于 `defineDocs`，请参阅 [`schema`](/docs/mdx/collections#schema-1)。

### 多种类型

与之前相同，您可以为不同类型（例如文档和博客）多次调用 `loader`。

```ts
import { createMDXSource } from 'fumadocs-mdx';
import type { InferMetaType, InferPageType } from 'fumadocs-core/source';
import { loader } from 'fumadocs-core/source';
import { meta, docs, blog as blogPosts } from '@/.source';

export const source = loader({
  baseUrl: '/docs',
  source: createMDXSource(docs, meta),
});

export const blog = loader({
  baseUrl: '/blog',
  // as mentioned before, you can leave `meta` an empty array
  source: createMDXSource(blogPosts, []),
});

export type DocsPage = InferPageType<typeof source>;
export type DocsMeta = InferMetaType<typeof source>;
```

以及相应的 `source.config.ts`：

```ts
import {
  defineDocs,
  defineCollections,
  frontmatterSchema,
} from 'fumadocs-mdx/config';
import { z } from 'zod';

export const { docs, meta } = defineDocs({
  dir: 'content/docs',
});

export const blog = defineCollections({
  type: 'doc',
  dir: 'content/blog',
  schema: frontmatterSchema.extend({
    author: z.string(),
    date: z.string().date().or(z.date()).optional(),
  }),
});
```
