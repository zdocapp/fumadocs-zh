## 概述

Fumadocs 15.2 在 `fumadocs-core` 之上引入了一个层，以扩展对其他 React 框架的支持，包括 React Router 和 Tanstack Start。其他框架也可以通过使用 `fumadocs-core/framework/base` 中的 `FrameworkProvider` 来获得支持。

### 为什么？

Fumadocs 的主要关注点是灵活性，我的目标是支持更多框架，只要这不改变 Fumadocs 的基本原则，比如核心包和 UI 包的分离。

React.js 生态系统使用起来非常愉快，将 Fumadocs 移植到其他框架并不像我最初想的那么困难。
我的目标也是让它不仅适用于 Next.js 开发者，也适用于生态系统中所有使用 SSR 兼容 React 框架的人。

### 破坏性变更

这是一个次要版本发布，它不应该破坏任何以前的用法，除非你在没有 `fumadocs-ui` 的情况下依赖 `fumadocs-core` 的底层 API。

Fumadocs Core 现在需要一个 `FrameworkProvider`。只需用适当的提供者包装它即可：

```tsx
import { NextProvider } from 'fumadocs-core/framework/next';

export function Provider({ children }) {
  return <NextProvider>{children}</NextProvider>;
}
```

如果你在使用 Fumadocs UI，则无需更改。`RootProvider` 默认包含了它，并允许你通过以下方式提供自己的框架：

```tsx
import { RootProvider } from 'fumadocs-ui/provider/base';

export function Provider({ children }) {
  // now it doesn't add the Next.js provider
  return <RootProvider>{children}</RootProvider>;
}
```

如果你发现任何公共 API 意外中断，请报告问题。

### 编译时间

15.2 版本还为 Fumadocs 带来了一些小幅性能优化，Turbopack 启动开发服务器并编译其首个文档页面的时间缩短至约 2-3 秒。

此项变更还使得 Fumadocs 有望在 Vite 上运行，在 Macbook 上，最小化 React Router 设置的生产构建仅需约 4 秒。

## 尝试体验

从您现有的 Next.js 文档升级：

```bash
pnpm update -i -r
```

如果您想尝试 React Router 示例：

```bash
pnpm create fumadocs-app
```

### 未来计划

15.2 版本不支持 Astro，并且除非 Astro 提供更好的 React.js 支持，否则很可能不会支持。

- Fumadocs UI 布局需要 `transition:persist`，但这也会影响其子元素（例如 MDX 内容），导致页面内容在导航后仍被保留。
- React 上下文无法跨 Islands 工作，这显著改变了 Fumadocs 的使用方式，因此需要重新设计 API。

Fumadocs 将继续以 Next.js 为首选，文档内容不会为了通用化其他框架的用法而更改。相反，将为其他框架开发一个新的文档站点（计划中）。
